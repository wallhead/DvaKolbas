# RTX 3050 release correction — 2026-10-07

The tester's v1.0 log identifies NVIDIA GeForce RTX 3050, vendor 10DE,
device 2507, driver 610.88, Skyrim 1.6.1170, and the Standard renderer
at source 4708828495e9. DLAA and NVIDIA presentation are selected.

Streamline reports NGX FrameGeneration `AdapterUnsupported`, disables
DLSS-G, and then rejects `slSetFeatureLoaded` for feature 1000. Community
NR has not initialized at this boundary. This is an edition/packaging failure,
not evidence of an NR model failure or a bad NR driver-core path.

The current DLAA/DLSS host initializes DLSS-G even when interpolation is off.
The Standard build has no RTX 20/30 compatibility code. Its saved
`NvidiaMFGUnlock=true` cannot enable code omitted at compilation.

The correction ships the Universal renderer with
`TRP_ENABLE_OPTIONAL_FEATURES=ON`. The existing controlled pre-Streamline
startup identifies the actual D3D12 adapter and prepares the Ampere provider
before feature loading. NVIDIA runtime files are unchanged on disk; controlled
compatibility transformations are process-local. FSR selects its own presenter.
The world pipeline remains DLSS/FSR -> NR -> FG -> UI.

`Pack-Release.ps1` now refuses a Standard renderer before creating an output
archive or staging directory. `ReleaseCompatibilityTests.ps1` reproduced the
old packer's acceptance of Standard, then passed with the Universal-only gate.

## Verification and limits

- Existing startup, INI, Ampere/Turing runtime, module-loader and planner checks:
  61 passed against the retained baseline test executables.
- An offline provider audit reads the actual bundled DLSS-G modules, verifies
  the production SM86 planner, publishes its transaction in the audit process,
  and verifies complete rollback. It does not create a GPU device or dispatch.
- Final clean Universal build, fresh compatibility test binaries, bundled-provider
  audit and package hashes are recorded in `rtx3050-verification.json`.
- Actual RTX 3050 startup, NR processing, image quality and FG cadence need the
  tester's log and gameplay check. Compiling the compatibility route does not
  qualify RTX 20/30/50 hardware. This correction does not resolve NR tone drift.

## Tester handoff

For a tester already using the complete v1.0 runtime bundle, replace only
`SKSE/Plugins/RaZkolbaS.dll` while Skyrim is closed. Keep
`[Compatibility] NvidiaMFGUnlock=true`. For the NVIDIA test select
`[Settings] UpscaleType=3` and `[FrameGeneration] Backend=1`; the temporary
FSR workaround INI instead selects 4/2 and must be changed back for this test.

First verify startup with FG disabled, then load a save and test NR off/on.
Then test FG on/off, HUD/inventory/map, camera movement, save/reload and alt-tab.
Send the complete new `RaZkolbaS.log` after the first attempt, including failures.
Expected startup includes `edition=Universal`, `selected route=Ampere`, and
`physical adapter=Ampere target=SM86`, followed by successful host initialization.

Reproduce the release rejection test with:

```powershell
pwsh -NoProfile -File tests/ReleaseCompatibilityTests.ps1 `
  -TemplateArchive '<existing-v1.0-zip>' -StandardDll '<retained-Standard-dll>'
```

Use the built `tests/turing/Release/TRPTuringProviderAudit.exe` with
`<bundled-Streamline-directory> <audit-output-directory> 86` for the offline
SM86 audit. The successful audit reports 70 programs, one temporal program,
208 transaction writes and verified publication/rollback.

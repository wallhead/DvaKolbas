# NR Before live-style freeze

The user reported a frozen Skyrim image when applying settings in the End menu. The preserved session loaded Standard source `0dc034839179`, DLAA at 2560x1440, NVIDIA FG off, and community RTX40 NR. At 08:32:15 a live Apply changed Style 1 to 0 with Stable colors off. About three seconds later the presenter's D3D12 device reported `DXGI_ERROR_DEVICE_HUNG` (`0x887A0006`); the outer D3D11 device remained healthy. Windows recorded a display-driver reset. No DLSS feature recreation was logged at that Apply. Earlier NR enable and Stable colors transitions completed successfully. This is a setting transition failure, not visual acceptance of the tone-stability build.

The native standalone probe reproduced device removal at the first asynchronous Style 1 to 0 change. A constant Style 1 control completed 150 sources. A private experiment that explicitly drained NR before switching completed 360 sources with 17 alternating changes. The tracked `NrLiveStyle-off` regression failed before the fix at source 21. These establish the transition/retirement requirement; they do not identify the vendor's internal shader or state mutation.

`BeforeUpscale` now compares the sanitized style against its last recorded style. A changed style waits for all prior vendor work and genuine delivery readers before new recording, then resets history. This uses the existing bounded retirement path and retains ownership on failure. It neither recreates the vendor feature nor adds a per-frame wait for unchanged styles. Other tuning changes retain their existing behavior. This fixes the qualified community Before entry shared by DLSS/DLAA and FSR; After-FG remains outside this checkpoint.

The encoder-gated `NrDeferredDelivery-style` test verifies that completed NR work alone is insufficient: the style change must wait for the actual D3D11 output/encoder reader. It failed before the fix and passes afterward, including history reset without a caller reset. Existing pressure tests verify unchanged styles remain asynchronous. Native `NrLiveStyle-on/off` tests alternate 1/0 every 20 sources, with no per-frame readback, and require successful GPU retirement. The prepared-FSR variant additionally consumes the genuine linear lease on the same presenter device. These are transition regressions, not FPS benchmarks. Three warmup sources exclude initial per-slot descriptor allocation from timing-completeness assertions.

Private full logs, raw timing receipts and the immutable Skyrim log are under `out/research/nr/tone-freeze-20261004`. Qualification records their hashes. The first stable-color cycle completed without a hang but failed a fixture assertion because zero warmup included initial descriptor creation; the fixture was corrected to three warmup sources, matching existing timing fixtures. No production workaround was added for that assertion.

# HDR diagnostic review corrections — 1.3.5

Scope: correct measurement quality in the approved ENB HDR investigation. The production inverse tone-mapping curve, INI defaults and local installed mod are unchanged. Deliver a separate DLL-only tester build, preserving the published 1.3.4 diagnostic artifact.

## Findings and disposition

1. **Calibration contamination confirmed and fixed.** At ordinary display sizes the 16 by 9 grid has eight samples inside the top-left patches. Previously they entered the output maximum and percentile. Patch pixels are now excluded from all scene/UI summary populations, so the ordinary population is 136 with patches and 144 without. The count is derived from actual integer texture geometry rather than assumed. Four separate patch reports contain expected luminance, measured mean/p95/max, sample count and maximum error. These measure GPU HDR codes; they do not replace the final-compositor or physical-display check.
2. **Banding risk confirmed; curve work remains pending.** Applying the current CPU reference to neutral 8-bit source levels 230–255 gives a largest adjacent step of approximately 32.18 nits for paper white 200, peak 1000, strength 1, start 0.6, Gamma22. The earlier extreme screenshot settings (152/4000 nits, strength 1, start 0.1, sRGB) give approximately 91.48 nits. These are mathematical source-quantization estimates, not observations of visible bands. The specific “B” INI was not supplied here, so its exact 20–25-nit estimate is unverified. Dithering the final PQ encoding cannot recover quantized source detail. A gentler shoulder and/or deliberate source reconstruction must be assessed in the next curve milestone; no untested dithering is enabled in this diagnostic fix.
3. **Display-peak coverage added.** Known displays now use absolute references 100, 200, 80% of reported peak and 120% of reported peak, with a 10000-nit PQ ceiling. Unknown displays keep 100/200/500/1000. The menu lists actual levels. Reporting a monitor's peak is not a physical measurement, and the above-peak reference may be clipped by the display.
4. **Global logging dependency removed.** A temporary `Capture HDR samples` control enables only HDR pixel sampling. `LogFrameDiagnostics` no longer needs to be enabled for this capture. Disabling capture clears the patch request; both options default off and are not saved to the INI.
5. **Last sample collected on normal retirement.** After existing successful interop drains in quiescence/target replacement, all pending reports are harvested and logged before resources are released. No extra wait was added. Abrupt termination/device failure can still prevent collection. No mapping is performed through the drain collection API before its caller has retired the GPU work.
6. **Sampling overhead remains an opt-in cost.** Logs now include command-recording CPU time (including first readback allocation) and map/analysis CPU time for each capture. GPU copy cost is explicitly outside these figures. This does not establish that the periodic GPU copies are free or remove their possible frame-time blip. Capture is off by default and should be disabled after the measurement.

## Verification

The new exclusion regression failed against 1.3.4 with `calibration pixels are excluded from scene statistics`, then passed after partitioning the samples. WARP tests compare the ordinary maximum/p95 directly with the unpatched subset of GPU pixels, check separately measured patch luminance within 1%, test a non-round 537-nit display reference and collect a final submitted sample without slot reuse. CPU tests cover unknown display fallback, patch bounds and the PQ ceiling.

Release plugin and HDR test targets build. Six focused checks pass: OverlayLayout, OverlaySettingsCommit, SourceDLSSGSession, HDROutput, HDROutputPass and SourceNvidiaFrameEvaluation. Final screen and gameplay validation remain the tester's next action.

# AMD NR foundations

This standalone subsystem reads an owned, bounded weight archive, identifies the
known archive, computes processing geometry, and converts numerical storage bits
on CPU or D3D12. It does not evaluate the NR network or enable AMD NR in TRP.
The exact known archive remains `KnownArchiveIncompleteSchema`, with
`inference=unavailable`. The plugin's renderer and top-level build are unchanged.

Only source and archive directory names/lengths are committed. The original DLL,
weights, extracted GPU objects, local decompilation, and generated bytecode are
not distributed. Neither tool loads the supplied DLL. Each format input/output
is a sequence of little-endian 32-bit words, including half/byte encodings in the
low bits. Outputs are published from a complete temporary sibling file; input
aliases are refused. Input budget is 256 MiB; the GPU probe additionally limits
one dispatch to 65,535 groups of 64 words.

## Build and test

Requires Windows x64, VS 2022 C++ Build Tools, Windows SDK, CMake 3.21+, and
Python for CLI fixtures. NumPy enables the independent differential tests;
CMake explicitly warns when these tests cannot be registered. No NGX, HIP,
Streamline, Skyrim, or renderer initialization is required.

```powershell
$amdNrCmake = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe'
$amdNrCTest = Join-Path (Split-Path $amdNrCmake) 'ctest.exe'
& $amdNrCmake -S tests/amd-nr -B out/amd-nr-foundations -G 'Visual Studio 17 2022' -A x64
if ($LASTEXITCODE) { throw 'configure failed' }
& $amdNrCmake --build out/amd-nr-foundations --config Release --parallel 2
if ($LASTEXITCODE) { throw 'build failed' }
& $amdNrCTest --test-dir out/amd-nr-foundations -C Release --output-on-failure --no-tests=error
```

Shader compilation happens at build time with strictness, IEEE strictness, and
warnings as errors. The source-owned `cs_5_1` kernel uses integer operations
and byte-addressed buffers; it does not depend on architecture-specific GPU code.
The D3D12 probe requires an explicit device and DIRECT queue from that device.
Jobs retain buffers, commands and fences across timeout or handle abandonment.
Failure to prove retirement retains the complete context until process exit.
The probe is a serialized diagnostic API, not a frame scheduler.

`AmdNrGpuFormats` requires the debug layer and returns an explicit skipped result
when Windows Graphics Tools is absent. `AmdNrGpuStorage` runs the real WARP
conversions without debug validation. These are different forms of evidence.
Its fixtures cover delayed fences, abandoned/repeated jobs, foreign jobs,
invalid queues/counts, and simulated retirement failure after actual completion.

```powershell
C:\Python314\python.exe tests/amd-nr/NumericOracle.py --cpu out/amd-nr-foundations/Release/TRPAmdNrInspect.exe --gpu out/amd-nr-foundations/Release/TRPAmdNrFormatProbe.exe --adapter-luid 00000000:00010318 --work-dir out/amd-nr-foundations/oracle-rtx4080
```

The known weights inspection returned 147,689,451 bytes, 153 records,
SHA-256 `6bf8dc931ef3ccffe18c82de26ab374156e7f19539ffcf8eabaa25dca5cf15ab`,
processing `1920x1088`, deepest `32x20`, and incomplete-schema status.
`--list` prints record metadata. Extent modes `default`, `8`, and `128` and
`--no-extra-height` are checked explicitly. Exit codes: 0 known archive/help or
successful conversion, 3 unknown archive, 2 malformed input/arguments/I/O.

Numerical CLI modes on both tools use `--format f32-to-f16|f16-to-f32|e4m3-to-f16
--input PATH --output PATH`; GPU additionally requires `--warp` or
`--adapter-luid HIGH:LOW`. No physical adapter is chosen implicitly.
Oracle fixtures, complete expected/actual outputs, and JSON reports remain under
the specified ignored work directory. Truncated, missing, malformed, and
bit-mismatched outputs fail instead of accepting a matching prefix.

## Verified scope and remaining work

On 2026-10-05 the NumPy oracle matched CPU, WARP, and RTX 4080 SUPER for 51,950
FP32 words (50,000 seeded random values and 1,950 boundary neighbors), all 65,536
half encodings, and all 256 E4M3 encodings, with zero storage-bit mismatches.
The C++ tests additionally cover every adjacent finite positive half midpoint
and both signs. Half expansion preserves signalling NaNs; FP32-to-half quiets
NaNs while retaining sign/payload; both E4M3 NaNs yield positive `0x7e00`.
Geometry uses checked 64-bit arithmetic before narrowing to positive signed
32-bit processing extents.

| Device | Identity | Result |
|---|---|---|
| WARP | 1414:008c, driver 10.0.22621.3672 | Storage conversions verified |
| RTX 4080 SUPER | 10de:2702, LUID 00000000:00010318, driver 32.0.16.1714 | Storage conversions verified |
| AMD Radeon integrated graphics | WMI 1002:13c0, driver 32.0.21043.5001 | Listed by WMI, absent from DXGI enumeration; not tested |
| Discrete RDNA2 / RDNA3 / RDNA4 | No representative selectable hardware | Acceptance outstanding |

The Windows debug layer is unavailable on this host, so GPU resource/state
validation remains outstanding. Numerical-format success does not establish
model output correctness, accumulation accuracy, quality, speed, or AMD
compatibility. All internal views for 153 records and all operations for 71
blocks still need recovery and validation, including FP8 encode policy,
window/skip layouts, noise, input color/exposure, history, and output codecs.
Only after those contracts have evidence can a precise network implementation
plan be written. Full inference, resident allocation, and TRP session/UI/reset
integration remain necessary for the original AMD NR request.

The probe follows the Windows SDK's [resource barrier contract](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12graphicscommandlist-resourcebarrier).

# Community NR Before: stable original colors

**Current status, 2026-10-04:** the user rejected this option because it weakens styles too much. `NRStableColors=false` is explicitly retained in the trial; this document describes the earlier implementation, not an accepted camera-drift fix. The user reports stable AIO19 gameplay. See the [current game reference and full-tone comparison](../research/nr/tone-contract/AIO_GAME_REFERENCE.md). The enabled-tone integration defect remains open.

The user selected stable original colors over preserving broad vendor tone/color grading. The implementation applies one SDR resolve after NR and before either upscaler and frame generation. This is a community Before-path option, not qualification of NR After FG, HDR, AMD, or untested NVIDIA hardware.

`[SourceDLSSG] NRStableColors=true` is the default when the key is absent. The community NR tab exposes **Stable colors**; Apply changes it for the current session, Save as default persists it. The host increments the settings revision and resets the vendor history once when it changes. False retains the previous exact NR-output copy. Disabled or paused NR leaves the source unchanged. Existing NR tone/style/intensity choices remain authoritative.

The bridge retains the original linear FP16 source and the raw NR result. A dense, source-guided 3×3 binomial neighborhood estimates the broad NR-minus-source color difference. The resolve subtracts that estimate from NR, preserves source alpha, and clamps to the existing SDR range. Source edges reduce cross-edge weighting. This requires no additional image allocation, GPU wait, queue flush, or temporal accumulation. Per-slot cached SRVs and an RTV use the existing images; the reader fence covers both shared source and raw NR reads. The complete producer context is restored after drawing. FSR's prepared lease remains linear FP16; DLSS/DLAA still receive the existing encoded delivery.

This deliberately attenuates medium and broad NR structure as well as tone. It does not preserve the exact vendor look. Adjacent sampling avoids the initial prototype's stride-four aliases: GPU tests retain at least 85% of two-pixel residual amplitude, 40% at four pixels, and 10% at eight pixels on a flat source. They also check uniform-grade removal, alpha at every pixel, sharp color edges, near-black values, context restoration, view reuse, invalid targets and alias rejection.

The fixed-surface regression uses 160 sources at 640×360. The surface and guides stay identical while its background changes dark → bright → blue → dark. It measures the last 20 sources of each 40-source phase. Raw NR at local tone 1 changed the surface's mean blue by about 22.55 encoded code values; stable colors reduced the largest settled mean channel range below 0.01 on the qualified RTX 4080 SUPER. Separate raw/off captures prevent constant-output or NR-bypass success; live stable/vendor switching is also checked. These are regional means, not proof that every pixel is invariant during Skyrim camera motion.

The earlier Graphics Tools exclusions are unrelated to this shader's test. Native GPU timing includes the draw in the existing **delivery** phase. The first 300-sample comparison at 2560×1440 measured delivery medians of 0.0304 ms raw and 0.07168 ms stable, with no descriptor creation after 120 warmup sources. This synthetic NR transaction is not a Skyrim FPS benchmark; clean-build qualification and receipts accompany the staged candidate.

Skyrim visual acceptance remains pending. In the same building scene, compare Stable colors off/on with NR enabled, first with FG off. Rotate slowly and quickly, then check NR off and FG on. Inspect original color/brightness stability, fine-detail quality, edges, dark scenes and HUD. Keep the raw option available if the user prefers its grading. Weather appearance profiles were not loaded in the earlier failing session; changing NGX HDR/auto-exposure flags did not change the controlled context probe. No vendor flag or runtime DLL bytes are altered by this fix.

The first Skyrim trial froze after Apply changed NR Style 1 to 0 with Stable colors off. The same live transition reproduced device removal in an asynchronous native GPU probe. The [live-style investigation](../research/nr/live-style/README.md) documents the retirement guard and regressions. Style changes now retire earlier GPU work and output readers before new recording; unchanged styles retain the fast path. Tone/color acceptance remains pending after that freeze correction.

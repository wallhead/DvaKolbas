# XeSS Frame Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution in this chat. Use superpowers:subagent-driven-development only if the user explicitly selects delegation. Steps use checkbox syntax for tracking.

**Goal:** Add selectable Intel XeSS FG with XeLL, preserving DLSS/FSR/XeSS -> NR -> FG -> UI and qualifying the first SDR trial on the RTX 4080 SUPER.

**Architecture:** Add an optional Intel presentation owner alongside the existing owners. Keep the game's stable D3D11 device/buffers separate from the native D3D12 Intel proxy; publish completed SR/NR colour and dedicated HUD through owned, fence-protected resources. Intel resource retirement and XeLL frame timing remain explicit contracts.

**Tech Stack:** C++23, MSVC, CMake/CTest, D3D11.4/D3D12, DXGI, official Intel SDK 3.0.2 FG/XeLL C APIs, existing PowerShell packaging and Capstone evidence tools.

**Spec:** [XeSS FG design](../specs/2026-10-09-xess-fg-design.md). Read the [AIO19 implementation evidence](../../../research/xess-fg/AIO19_XESS_FG_IMPLEMENTATION_2026-10-09.md) with it.

Status: approved for native implementation by the user on 2026-10-10. Tasks 1–6 are complete. Standalone Intel interpolation and visual/HUD checks qualified on the 4080 SUPER; Skyrim engine timing remains open.

## Global Constraints

- Official SDK 3.0.2, commit `8fe81bdbbaf00b3c1b733fd0d830c333dc84e6f0`.
- Add `[FrameGeneration] Backend = XeSS`; append internal backend value `3` and `GenerationBackendPreference::Xess`. Preserve `0=Ordinary`, `1=NVIDIA`, `2=FSR` and existing Auto policy.
- Menu label `XeSS FG (2x)`; at most one generated frame on every vendor in the first implementation. No Intel MFG or private provider patches.
- Backend selection is startup-only; Enabled remains live. No new minimum-FPS gate and no fake nominal 2x output statistics.
- First qualification is SDR, Native scale, fixed display extent, borderless, with the mod's HDR output disabled for this route. Windows display settings remain user-owned. HDR requests receive a precise startup diagnostic; no silent substitution.
- Required native device and direct queue are on the rendering D3D11 adapter LUID. Non-Intel needs SM 6.4; capability/context checks supplement marketing names.
- Require XeLL, disable the mod's competing Reflex path, and do not initialize AMD/NVIDIA FG underneath Intel. Preserve driver conflict warnings without modifying global settings.
- Standard After order is SR -> NR -> XeSS FG -> dedicated UI -> output. Retain explicit NR Before and maximum three passes; existing NR device eligibility remains unchanged.
- Initially tag guide/HUD inputs with `RV_ONLY_NOW`, with explicit copy-source state and a submitted tagging-fence proof. No AMD retirement acknowledgements in the Intel owner.
- SDK IDs are checked 32-bit values linked to engine source ID/epoch. Sleep, markers, tags, constants and Present agree; ID wrap requires a drained epoch reset.
- Engine marker locations must be verified. A renderer jitter hook or a fabricated Present-time marker cluster is not proof of pre-input latency integration.
- Missing Intel DLLs cannot break other providers. Explicit unsupported Intel requests fail with a readable stage/device/runtime diagnostic before committing game sizing/jitter.
- Stop admissions before teardown; GPU/device-loss or destroy failure never grants permission to release pending resources. Destroy FG before XeLL after proxy quiescence.
- Reuse the current worktree/build/dependency directories. Keep installed mod, INI and MO2 settings until a qualified trial is ready. No benchmark comparison is required.

## Review Focus

1. Laptop rendering/display adapters differ: use the producer's LUID and reject a mismatched native owner (Tasks 1/4).
2. Loading, duplicated sources or extra Presents occur: present real frames without invented simulations or stale-guide interpolation (Tasks 2/3/6/9).
3. HUD alpha/extents differ or capture is incomplete: suspend FG rather than generate distorted UI; pixel-test composition (Tasks 2/4/6).
4. Disable, minimize, settings or destroy occur while readers are pending: retain resources on failed quiescence (Tasks 3/5/11).
5. A pending backend choice changes UI validation while the current owner runs: live Enabled controls the actual owner; Save/restart controls backend (Tasks 8/11).

## Build and verification convention

Use `out/build/fsr-fg-universal`; new optional flag `TRP_ENABLE_XESS_FG` is independent of the SR flag so DLSS/FSR can use Intel FG without building XeSS SR. Reuse `TRP_XESS_SDK_DIR` for the pinned SDK root. Add `cmake/XeSSFG.cmake`, included beside `cmake/XeSS.cmake`, to define the owner library and tests under `TRP_BUILD_COMPATIBILITY_TESTS`.

For each test cycle: add the named regression, build its target, confirm the stated assertion fails before the implementation, implement the task, rerun the named group to PASS, inspect the task diff and commit it. The commands are:

```powershell
cmake --build out/build/fsr-fg-universal --config Release --target <target>
ctest --test-dir out/build/fsr-fg-universal -C Release -R '<group>' --output-on-failure
```

Replace placeholders with the exact target/group below. New GPU launchers use the existing Skyrim-process guard, produce bounded machine-readable receipts, and mark missing device/focus/SDK evidence NOT QUALIFIED. Graphics Tools is optional. Do not launch GPU tests alongside Skyrim. Product builds with Intel FG disabled continue to compile without its headers/DLLs.

## File and interface map

All new product units are under `src/FrameGen/`; use namespace `TheosRenderPipeline`. `Result<T>`, `RuntimeError`, `Extent`, `UpscaleFrame`, `UpscaleOutcome` and `ColorEncoding` refer to the existing `Upscaling` types.

- `XessGenerationRuntime.h/.cpp`: local, pinned public exports and retained module owners; `XessGenerationFunctions` and `XellFunctions` store SDK-typed function pointers.
- `XessGenerationFrameAdapter.h/.cpp`: `XessGenerationFrame` contains SDK constants, render/display/guide extents, immutable init flags, source ID/epoch and SDK ID. `AdaptXessGenerationFrame(const UpscaleFrame&, uint32_t sdkId) -> Result<XessGenerationFrame>` validates/converts camera and guide conventions.
- `XessGenerationPolicy.h/.cpp`: `XessGenerationAdmission { bool presentReal, tag, generate, reset; }`; `XessGenerationHistory::Decide(const UpscaleFrame&, UpscaleOutcome, bool requested, bool hudComplete, bool menu) -> XessGenerationAdmission`, plus `Accept(uint64_t sourceId, uint64_t epoch)` and `Invalidate()`.
- `XellSession.h/.cpp`: context lifetime, sleep mode, ordered SDK IDs/markers; SDK context outlives FG.
- `XessGenerationTransport.h/.cpp`: owned D3D11/D3D12 scene, guide and HUD copies; queue ordering and copy retirement.
- `XessGenerationPresentation.h/.cpp`: public Intel proxy/context, explicit UI policy, Present/status and teardown; no game-facing device emulation.
- `XessGenerationHost.h/.cpp`: connects host source acceptance, actual engine timing and stable game wrapper to the owner; no Intel callbacks into game objects.
- `XessGenerationEngineTiming.h/.cpp`: qualified source-loop boundary contract and guarded engine hooks; keep runtime-specific relocation evidence separate from the SDK owner.
- `cmake/XeSSFG.cmake`: isolated optional build and named checks. Test prefix is `XessFg`, distinct from the existing XeSS-SR-to-FSR `XessGenerationPolicy` test.

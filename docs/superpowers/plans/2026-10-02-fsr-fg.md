## SDK serialization and per-source transaction

One session mutex serializes all access to both SDK contexts. No host/UI/settings locks may accompany a potentially blocking SDK call. Closing stops admissions; owners stay alive until admitted calls finish. Call ownership is explicit:

| Operation | SDK lock ownership |
| --- | --- |
| Context create/destroy, provider/context queries, SDK configure/debug setup | Caller owns the session lock |
| FG Configure(N) followed by PrepareV2(N) | One caller scope owns the same session lock across both |
| UI registration/unregistration, swapchain queries, resize, WaitForPresents | Caller owns the session lock; worker callbacks never need it |
| Present/Present1 with generation callback installed | Caller owns the session lock, including disabled-source presents |
| Synchronous generation callback | Inherits Present ownership; MUST NOT reacquire; only dispatches the supplied descriptor |
| Debug/test-only async UI callback | Never takes this mutex or host/UI/settings locks; no Skyrim/ImGui/D3D11 access |

First stage prepares at the final handoff, after UI eligibility is known. This avoids a second same-source Configure to undo a late UI failure. UI may finish before Configure; the SDK ordering requirement is still Configure -> Prepare -> Present. Configure every consumed source, including menus, recovery and low-rate suppression; disabled sources skip Prepare. Early feature-less startup and DXGI_PRESENT_TEST do not consume IDs. Duplicate/out-of-order source IDs are rejected before SDK transaction admission; never configure the same consumed ID twice. A forward discontinuity configures the new ID disabled and resets reentry, using the SDK discontinuity contract rather than fabricating intervening frames. SDK owns callback descriptors/command-list submission; callback context survives retirement/destruction. The callback may retain its return code in bounded scalar state; diagnostics are emitted after Present, with no allocation, host locks or logging inside the callback.

Analytical rate policy (TRP defaults, not SDK constants): rolling mean of 8 positive source deltas; suppress after 3 successive means slower than 60 FPS; resume after 8 successive means at least 66 FPS and otherwise valid frames. During initial history filling stay disabled. A delta >=100 ms, invalid time or source-ID discontinuity immediately suppresses, clears the window and arms reset. On reentry configure enabled, Prepare(reset=true), then let the SDK determine the reset frame's generated outcome; successful Prepare acknowledges history, not proof of a useful generated frame. Later ML policy is not implemented.

Teardown/resize order: stop new admissions; under the session lock disable FG and detach callbacks/HUDLess references; unregister UI (null/flags 0); WaitForPresents; retire Prepare and transport-copy submissions; destroy FG context; destroy swapchain context; release final proxy COM reference; close TRP-owned duplicated latency handles; release transport/runtime. Failures retain live owners. Concurrent Present-vs-Prepare/disable/destroy stress tests must prove serialization, no callback re-lock and no use-after-free.

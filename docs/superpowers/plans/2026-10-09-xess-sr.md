# XeSS SR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if the user selects delegation. Steps use checkbox syntax for tracking.

**Goal:** Add validated XeSS SR with Native and scaled modes, then qualify existing NR and FSR/NVIDIA FG combinations.

**Architecture:** Use official Intel SDK 3.0.2 on the existing same-adapter D3D12 interop owner. Separate runtime loading, temporal contracts, SDK context and shared resources. Intel FG/XeLL is a later project with its own presentation design.

**Tech Stack:** C++23, MSVC, CMake/CTest, D3D11.4/D3D12, official XeSS C API, existing PowerShell/Python packaging tools.

**Spec:** [XeSS SR design](../specs/2026-10-09-xess-sr-design.md).

Status: approved for native execution in this chat by the user's “go next”, 2026-10-09. Tasks 2–8 are in progress; installed Skyrim files stay unchanged until a validated trial.

## Global Constraints

- Official SDK 3.0.2, commit `8fe81bdbbaf00b3c1b733fd0d830c333dc84e6f0`.
- Package only the D3D12 SR dispatcher initially: `RaZkolbaS/XeSS/libxess.dll`, SHA256 `251659dd84a3e84de67c886a4186e01f3eca49b00641906fe38bb6b807e5d5b7`.
- Initial validation uses SDR and the current ENB source. HDR, dynamic resolution, Intel FG and XeLL are outside this SR implementation.
- Standard order: scene → XeSS SR → NR After → selected FG → UI → output; existing explicit NR Before remains supported.
- NR remains limited to its existing supported NVIDIA routes. Existing automatic provider choices and startup defaults remain unchanged.
- Render-scale choices: Native, Quality, Balanced, Performance; sizing from the SDK, not fixed FSR ratios.
- Initial trials start with NR/FG off. Existing installed mod/INI files are untouched until a validated trial package is ready.
- Runtime/context/resources remain owned through confirmed GPU and downstream-reader retirement. A timeout never authorizes release of pending resources.

## Review Focus

1. A laptop renders on a different adapter from the primary display: use the D3D11 device LUID; test the mismatch in Tasks 2/4.
2. An optional runtime is missing on AMD or old NVIDIA: preserve ordinary DLSS/FSR startup and show a requested-XeSS diagnostic; test Tasks 2/5/8.
3. Colour or guide subrects do not match, including non-square resolutions: reject before temporal dispatch; test Tasks 3/4/6.
4. A minimize/resize or live NR change occurs with an FG reader still pending: retain the old resources until retirement; test Tasks 4/6/7.
5. The SDK fails after startup sizing/jitter has committed: use coordinated recovery, never silently relabel the output; test Tasks 4/5/8.

## Build and test convention

Extend the current configured `out/build/fsr-fg-universal` directory for integrated checks; do not create another full dependency checkout. Add standalone XeSS targets under `TRP_BUILD_COMPATIBILITY_TESTS`, with optional `TRP_ENABLE_XESS` and `TRP_XESS_SDK_DIR` configuration. Product builds without XeSS must remain valid.

For each task below: add its failing regression, build its named target, run the indicated CTest group, implement the smallest change, rerun that group, then commit only the task's files. Use:

```powershell
cmake --build out/build/fsr-fg-universal --config Release --target <target>
ctest --test-dir out/build/fsr-fg-universal -C Release -R '<group>' --output-on-failure
```

`<target>` and `<group>` are replaced with the exact values in each task. GPU runs also require Skyrim closed and the existing GPU probe guard. Report unavailable hardware as NOT QUALIFIED; never turn that into PASS. Avoid broad test reruns unless a shared change or failure warrants them.

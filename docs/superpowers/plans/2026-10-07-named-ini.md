# Named INI layout implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline, task by task.

**Goal:** One readable INI with named providers and quality modes, Native in both provider sections, and advanced options lower down.

**Architecture:** A generated public schema maps readable names into the existing renderer's internal numeric settings. All production file loads use the same decoder and menu saves use its inverse. Existing renderer algorithms, provider selection, buffers and ownership are unchanged.

**Tech stack:** C++23, SimpleIni, Python schema generator, PowerShell packaging, CTest.

**Spec:** User request and `C:/Users/user/Downloads/RAZKOLBAS_INI_LAYOUT_PROPOSAL.md`, adjusted by the user's choice of one organized INI with advanced settings lower down.

## Constraints and rulings

- Keep independent DLSS/FSR quality and sharpness. Native DLSS selects DLAA internally without a public DLAA mode.
- Derive normal FG presenter from upscaler. Keep ordinary FSR presentation in the advanced diagnostic section.
- No ConfigVersion and no automatic old-layout support, as previously requested by the user. An explicit offline converter can preserve installed values.
- Keep independent FSR/NR encoding: they can describe different pipeline formats. Do not silently change encoding.
- Preserve inactive NR pass overrides even when linked; omitting them would lose the saved settings after a restart.
- Keep one file. Menu geometry and appearance state go last; diagnostic, runtime and reconstruction settings go below ordinary settings.
- Unknown settings and comments survive Save. Existing startup-only path edits on disk remain authoritative.
- Worktree `C:/Users/user/.codex/worktrees/fsr-sr/DvaKolbas`, branch `codex/nr`. Do not alter MO2 profiles or install into a running game.

## Review focus

- DLSS Native must reach the existing DLAA path, while changing to FSR cannot erase the inactive DLSS Native selection.
- AMD normalization must operate after decoding and preserve an explicit FSR4 SR/FG request.
- Invalid named enums must report the public section/key and stop before creating GPU resources.
- Saving from the End menu must encode the next-launch request rather than overwrite it with active settings.
- Packaging must use the current generated template and apply the same value transformations as runtime.

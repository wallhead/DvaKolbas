## User requirements and clarified intent

The user requests four NR paths: NVIDIA RTX 50, NVIDIA RTX 40, NVIDIA RTX 20/30, and AMD RX 6000/7000/9000 displayed as unsupported for now. Use the three supplied NVIDIA DLLs and RazKolbas as a reference. Community compatibility shims and justified byte patches are authorized methods.

The user clarified **one NR pass, Before or After**, not both placements together. They explicitly selected **After FG, including generated frames**, rather than the AIO order of after SR but before FG. Enable/disable and placement must change in-game without restarting Skyrim. DLSS/DLAA and FSR/NativeAA must work with NR on eligible NVIDIA hardware, including their existing supported FG routes and FG off. AMD NR remains unsupported regardless of selecting FSR.

“One pass” means one NR evaluation per image processed at the selected stage. Separate temporal feature ownership for real/generated image streams, if required, is not a second sequential NR pass on one image. Preserve existing two-pass settings as legacy data without enabling a second pass in this new mode.

## Approach and alternatives

Recommended: extract a shared NR owner independent of the selected SR/FG presenter, use the FSR per-image presentation callback for After, and develop a narrowly versioned DLSS-G post-generation integration boundary. Reuse the existing NR reconstruction code and reviewed retirement behavior where their contracts match. This minimizes changes to accepted SR/FG paths while meeting the exact new ordering.

A native-present interception for both providers could centralize processing, but it starts too late unless HUD-less color, guides, queue, output identity and UI ownership are recovered. It creates additional pacing and hook-chain risk. Replacing both presenters with a wholly owned generation scheduler would offer more control but has a larger private-ABI and latency validation burden. Neither alternative is assumed necessary before the narrow provider adapters are investigated.

The DLSS-G post-generation boundary is an explicit feasibility gate. Public Streamline options/state expose no equivalent per-image callback in the inspected pinned headers. Do not invent an output export, reinterpret an input-completion fence as generated-output ownership, or relabel late pre-FG NR as After.

## Compatibility loading and patch policy

First prove direct D3D12 NR entry points plus the minimum driver-core parameter interface on the actual adapter. Adapt RazKolbas's profile-specific caller identity shim if the unmodified path reproduces its failure. The supplied RTX 50 file is signed; it does not inherit a patched-file shim by assumption.

Do not disable process-wide signature verification or modify Windows trust settings. If a runtime check prevents a needed path, locate its exact cause in a standalone probe. A byte/IAT patch is allowed when needed, with a version/hash-specific descriptor, verified original bytes/pointer, bounded target and ownership-aware restoration. Preserve pristine inputs; file-patched outputs are separate working copies. No binary publication is implied by this design.

Retain core-module references, runtime file leases, callback code and in-flight GPU resources for their actual lifetimes. Failed release/shutdown, an unfinished recording or uncertain retirement retains ownership and reports a terminal failure; a timeout does not authorize release.

## Stage contracts and render order

Before:

```text
game HUD-less color + matching real-frame guides
  -> NR once at render extent
  -> selected DLSS/DLAA or FSR/NativeAA upscale
  -> optional FG
  -> native UI/overlay composition and presentation
```

After:

```text
game HUD-less color + real-frame guides
  -> selected upscale
  -> optional FG
  -> NR once for each real/generated HUD-less output image
  -> native UI/overlay composition exactly once
  -> presentation with provider pacing retained
```

With FG off, After means one NR evaluation after SR on the real image. After results are not fed back into FG input history. NR works on world pixels; the dedicated HUD remains at native resolution and is composed after NR. ENB/ReShade's established source/effect ownership must remain coherent; no duplicate effect invocation on generated outputs.

The shared NR stage receives an owned immutable packet: epoch, source pair and image identity, real/generated classification, interpolation fraction/presentation timestamp when applicable, color resource/encoding/extent, guide resources/encoding/extent/provenance, reset, device/LUID, command-list/queue contract and UI-completion ownership. It returns a recorded output plus explicit retirement requirements and an evaluation result. A DLL load or initialized context is not “NR active”.

### FSR post-FG adapter

Use the pinned `FfxApiPresentCallbackFunc`: it identifies real/generated frames and supplies current image, UI, destination and the command list executed before presentation. The adapter records world NR, then verified native UI composition into the final destination. It uses D3D12-only work and frozen settings; no game, D3D11 or ImGui calls from AMD worker callbacks. When After NR is off, retain or restore the accepted automatic-composition route at a proven quiescent boundary. Callback mode must independently match its pixels, alpha behavior and pacing.

### NVIDIA post-FG adapter

Recover a concrete post-generation/HUD-less-output boundary in the exact installed Streamline/DLSS-G stack. Candidate interception of the inner presentation path or private generation completion is research until resource descriptions, frame identity, queue/fence ownership, writable output and separate UI are observed. Use an exact version/hash-specific hook if public interfaces cannot supply it. Do not execute NR on the application's input backbuffer and call that generated-frame coverage.

The shipping adapter must prove every displayed image in the supported generation mode traverses NR exactly once, including generated images. Keep source and generated counts separate. Preserve Reflex, pacing, retained swapchain identity and native UI. Existing MFG behavior with NR off stays intact; requested After combinations lacking qualified output coverage must be reported unavailable rather than silently skipping generated images.

### Generated guide/history gate

The public FSR present packet exposes color/UI, not interpolated NR depth/motion. The DLSS-G equivalent is not established. Therefore generated guide provenance is a separate required experiment: recover provider output guides if available, or implement and qualify an explicit reconstruction from the retained source pair. Color alone is not sufficient evidence of temporal NR correctness.

Never assign real-frame guides to a generated image while claiming matched guides. Record interpolation time, direction/scaling, depth convention, occlusion behavior and resource retirement. Define the temporal history schedule only after observation establishes whether the runtime accepts the all-image stream or requires distinct retained histories. If no credible guide/output contract can be demonstrated, true After FG remains incomplete; there is no fallback acceptance of the old AIO ordering.

## Live settings and lifecycle

One authoritative settings snapshot serves INI, Apply/Save/Discard and overlay. Add explicit Before/After placement and GPU-path status, keeping requested/effective/pending/failure states distinct. Enable/disable, placement and supported tuning apply at an image-batch boundary without restarting Skyrim. Settings cannot change between generated and real outputs belonging to the same batch.

Placement changes stop admission, retire the old stage's work/readers, switch the retained feature/resource contract and request history reset. No presenter or device replacement is required. Off bypasses NR while preserving SR/FG. Re-enable resets on the first eligible image. Reallocation may briefly suspend NR; status explains it. Parameter-only changes avoid unnecessary reload/reallocation.

Menus/loading, missing guides and camera cuts use explicit per-stage admission/reset rules. Resize/minimize/shutdown retire both source-side and provider-side readers. Off/on, placement changes and callback detach cannot release a feature still recording or executing. No callback reacquires a host lock held through provider Present; queue ownership must be proven before wait/barrier insertion.

An NR-only admission/init failure preserves the last valid unenhanced image and working SR/FG when retirement is proven safe. Device/presentation or uncertain ownership failures follow the existing rendering fault path. Do not retry an uncertain teardown in a destructor.

## AMD presenter and lifecycle

The presenter uses only NewDX12 with its retained matching D3D12 queue and two application buffers. Legacy HWND/extent/refresh/scanline/scaling/usage/supported flags are preserved; unsupported fullscreen, MSAA, format, usage and flags have explicit field diagnostics. A scoped internal-factory guard prevents future factory-hook recursion, and a short-held HWND reservation prevents a second owned AMD presenter. Context/version/override creation descriptors are members. No alternate creation API is retried after failure.

Under one SDK session lock, each source is admitted once, converted, configured, optionally prepared and submitted with its guide fence, copied to the application/UI buffers, registered on the separate swapchain context and presented through the production generation callback. Test and feature-less startup presents consume no source ID. Disabled sources still register complete native UI. The callback inherits the lock and dispatches the SDK descriptor unchanged; no manual interpolation list/output query enters production.

Shutdown stops admissions, detaches generation callbacks, unregisters UI, waits for SDK presents, seals/drains native producer/Prepare/copy work, destroys FG and swapchain contexts, releases final swapchain references and then releases transport/runtime. Any failed boundary retains its owners. The implementation-review fixes below supersede the original dimension-change replacement: ordinary resize now retains the AMD swapchain and native devices while rebuilding fixed-size feature resources. Unsubmitted failed Prepare work can be closed/discarded without fabricating a fence.

## Completed host integration (Task 7)

The AMD presenter is selected before publishing the outer game swapchain. A bounded FsrHostPresentation owner prequeries analytical SR sizing on the original D3D11 producer and retains its shared SR resources/runtime. The game receives a stable reduced D3D11 texture and original producer from GetDevice; the AMD inner buffers remain D3D12. Full SR creation stays deferred until the original device creation returns. FG creation waits for the first accepted temporal frame's measured SR camera/input policy. Feature-less completed menu frames still publish the scene and UI.

Present and Present1 use the same tested source boundary, with one SR/effects pass and completed native UI before SDK submission. Dirty/scroll Present1 calls fail before source consumption. Test presents only probe the presenter. Real outer Present count + 1 supplies the same source identity to SR, jitter and FG; generated outputs never advance it. Guide reuse waits before SR overwrites. Native HUD, ImGui and ReShade GUI remain outside the reconstructed scene even when Skyrim draws no UI: an empty HUD is cleared before late foreground draws, then frozen at final handoff. Loading fade preserves UI alpha.

Resize validates descriptors, masks, queues and immutable flags before retirement. Caller queues never reach the D3D12 SDK. After SDK and bridge readers retire, the same AMD chain receives ResizeBuffers; SR/FG contexts and size-dependent resources are rebuilt on the retained native devices. Cached waitable handles and maximum-frame-latency state remain associated with that chain. A rejected native resize restores resources using its actual descriptor and returns its original HRESULT; retirement/reconstruction failures latch a rendering failure and retain owners. Null/all-zero masks are accepted for specified counts; a non-null mask array with count 0 is rejected without reading an unspecified length. This follows the array sizing contract in [Microsoft ResizeBuffers1 documentation](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_4/nf-dxgi1_4-idxgiswapchain3-resizebuffers1).

Compiled startup/settings admission requires analytical SR, dedicated NativeUI, fixed SDR extents and TRP ownership. Changing presenter requires restart; live FG on/off keeps the AMD chain. Apply/Save preserves that request. Native controls distinguish requested, warming, rate-suppressed, active and failed. An observed callback is required for an active label; it does not claim physical scan-out. Ordinary/SR-only builds retain their existing routing. ReShade native ownership is captured through its public API; recognized incomplete injector exports or missing native capture are rejected before reduced buffers are published.

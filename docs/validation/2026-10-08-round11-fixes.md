# Round 11 repairs

Scope: the independent DLSS/DLAA -> community NR -> FSR FG candidate on `codex/nr`. The user authorized fixing appropriate findings from the supplied static review. Rendering order remains DLSS/FSR -> NR -> FG -> UI.

## Changes

- R11-1: encoding guidance uses the public schema's `[FSR] SourceColorEncoding` reference. Startup diagnostics distinguish presentation ownership, provider settings and explicit SDR encoding. The message audit rejects unknown INI sections, while allowing explicit instructions to remove known obsolete keys.
- R11-2: explicit NVIDIA FG with FSR upscaling is rejected with the conflicting public choices identified. Selecting FSR upscaling in the menu clears the unavailable NVIDIA preference to Auto.
- R11-3: source resets are consumed before evaluation and rearmed only by source failure/recovery. FG skips rely on the presenter's independent history. Pending source resets can drain during ordinary FG inhibition.
- R11-4: guide-convention changes retire SDK readers and recreate only the FG feature. The swapchain, shared guides and scene/UI transport stay owned. Any retirement/recreation failure blocks new admissions and retains owners for final cleanup.
- R11-5: external NGX render dimensions are queried and checked before retiring NR, FG or source buffers. Rejected sizing leaves the running source intact.
- R11-6: spatial source recovery remains visible in the ordinary FG page. Consecutive recovery frames report the last NGX result, warn once, log an error every 120 frames, and report temporal recovery. The redundant unreachable branch was removed. A usable spatial image is retained rather than terminating Skyrim solely because the recovery counter reaches a threshold.
- R11-7: menu and generated INI comments explain that Reflex and NVIDIA's output FPS cap apply to NVIDIA presentation and are unavailable with FSR FG, including mixed DLSS sources.
- R11-8: staging FSR FG leaves the running NVIDIA controls visible until restart.

R11-9's claim that text choices are not validated is not reproduced: `PublicIni::Decode` validates every nonempty choice table, including source encoding and NR profile. Old INI rejection is intentional per the user's earlier request. Driver/runtime trust rules and payloads are unchanged. Candidate archives remain separate from the original v1.2 release and are identified by a clean source revision and exact hashes.

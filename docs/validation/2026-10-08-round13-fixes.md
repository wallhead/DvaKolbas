# Round 13 fixes — v1.3.3

2026-10-08; branch codex/nr; reviewed input: COMMIT_REVIEW_2026-10-08_ROUND13.md.

## Findings and selected repairs

- R13-1 confirmed with a production-code probe: TITAN RTX was FSR-only
  both without NVAPI and with a matched Turing report. Shared narrow/wide
  whole-word RTX recognition now handles trailing RTX, bare RTX and
  workstation names, and rejects substring lookalikes and GTX16.
  NVAPI architecture remains the NR family authority; names never infer it.
- R13-2 confirmed: same-LUID linked/multiple logical mappings disabled the
  entire NVIDIA route. GpuArchitecture now explicitly marks this ambiguity.
  Renderer eligibility may fall back to that adapter's reviewed PCI ID or
  DXGI RTX name. NR explicitly rejects ambiguity, even if other fields are
  positive. Foreign LUID reports and broken empty physical mappings cannot
  use this fallback. Actual NVIDIA feature capability checks remain in force;
  the change does not qualify linked-GPU FG.
- R13-3: optional layout loading now reads only geometry and returns defaults
  plus a warning on IO failure. It never modifies the file. Strict renderer
  startup loading is unchanged. Overlay Init is once per device startup, not
  on every End-key opening, correcting the review's scenario description.
- R13-4: README records Intel FSR routing as physically untested. Existing
  provider policy already excludes Intel ML, so Auto falls back to FSR3 and
  explicit FSR4 is unavailable. No broad Intel hardware claim is added.
- R13-5: removed unreachable negative-result branches in telemetry and
  swapchain startup readers. Save-for-update failure handling is preserved:
  an unreadable existing file must not be overwritten.
- R13-6: repeated NVAPI observations retained. This optimization is not
  required for the verified bugs; independent actual-device/LUID checks
  continue at each NR ownership boundary.

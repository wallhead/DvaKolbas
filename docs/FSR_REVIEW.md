## Findings and fixes

1. Ordinary FSR presentation had no manual ReShade ownership handshake. Before/after settings were inert, leaving automatic presentation effects responsible for the image. The actual ordinary-presenter fixture first failed with an automatic runtime remaining active. The integration now captures the native swapchain during its own synchronous creation using the public `init_swapchain` event and `get_native` handle, retains that chain, and releases the automatic proxy/runtime before publishing it. Registered runtimes without provable ownership fail explicitly. The existing manual runtime then processes source effects and completed UI separately. It neither destroys an automatic runtime with the manual-runtime export nor accesses private proxy GUIDs/offsets. [ReShade's public event and native-handle API](https://crosire.github.io/reshade-docs/namespacereshade.html) define these boundaries.
2. The immediate NVIDIA FG checkbox left the new settings draft stale. Apply/Save wrote the old value back. The behavioral test reproduced that reversal; the checkbox now updates both the draft and the immediate runtime request. Regression scenarios use the production Apply and persistence boundaries for both toggle directions, Apply versus Save, unrelated edits and saved-startup round trips.

The supplied ReShade 6.7.3.2150 runtime passes isolated ordinary and NVIDIA presentation fixtures, with before/after/after placement switching, exactly one effects invocation per source frame, native UI unchanged by effects, downstream presentation preserving completed UI, depth semantics, input, screenshots and runtime retirement/recreation. ReShade remains an optional, explicitly supplied fixture dependency; no injector is installed or downloaded by CMake. `tests/run_reshade_integration.py` runs each route in its own temporary directory. `TRP_RESHADE_INTEGRATION_RUNTIME` enables this check in CTest.
